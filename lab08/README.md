# Практическая работа № 8 — вариант 3

## Расширение: промоакции

Созданы три новые таблицы:

- `lab.promotions` — параметры акции;
- `lab.promotion_products` — товары, участвующие в акции;
- `lab.promotion_sellers` — продавцы, участвующие в акции.

## Бизнес-правила

1. Каждая промоакция имеет уникальный `promotion_id` — `pk_promotions`.
2. Код промоакции уникален — `uq_promotions_code`.
3. Комбинация названия и интервала акции не должна повторяться — `uq_promotions_name_dates`.
4. Дата окончания не может быть раньше даты начала — `ck_promotions_dates`.
5. Скидка должна быть больше 0 и не больше 100 процентов — `ck_promotions_discount`.
6. Одна акция может распространяться на много товаров, а товар может участвовать в разных акциях — таблица `promotion_products`.
7. `promotion_products.product_id` обязан существовать в `olist.products`.
8. Одна акция может распространяться на много продавцов, а продавец может участвовать в разных акциях — таблица `promotion_sellers`.
9. `promotion_sellers.seller_id` обязан существовать в `olist.sellers`.
10. При удалении промоакции её связи с товарами и продавцами удаляются каскадно.

Тестовые связи с товарами и продавцами формируются непосредственно из реальных идентификаторов Olist, поэтому внешние ключи воспроизводимо проходят проверку.
