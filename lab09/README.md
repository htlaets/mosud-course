# Практическая работа № 9 — вариант 3

## Исходное отношение

`promo_flat(promo_id, promo_name, start_date, end_date, product_id, category_name, seller_id, seller_city, discount)`

## Функциональные зависимости

По бизнес-правилам методички:

- `promo_id → promo_name, start_date, end_date, discount`
- `product_id → category_name`
- `seller_id → seller_city`

Для строки, описывающей сочетание акции, товара и продавца, потенциальный ключ:

`K = {promo_id, product_id, seller_id}`

Замыкание ключа:

1. начинаем с `{promo_id, product_id, seller_id}`;
2. по `promo_id` получаем `promo_name, start_date, end_date, discount`;
3. по `product_id` получаем `category_name`;
4. по `seller_id` получаем `seller_city`.

Следовательно, `K+` содержит все атрибуты исходного отношения.

## Частичные и транзитивные зависимости

Так как ключ составной, имеются частичные зависимости неключевых атрибутов от частей ключа:

- атрибуты акции зависят только от `promo_id`;
- категория зависит только от `product_id`;
- город продавца зависит только от `seller_id`.

В заданном наборе функциональных зависимостей отдельной транзитивной зависимости между неключевыми атрибутами не задано.

## Аномалии плоской таблицы

**INSERT:** нельзя удобно добавить новую промоакцию, пока ещё нет конкретной пары товара и продавца, не вводя `NULL` или фиктивные значения.

**UPDATE:** название, даты и скидка одной акции повторяются во множестве строк; изменение только части строк создаст противоречие.

**DELETE:** удаление последней строки конкретной акции может одновременно уничтожить сведения о самой акции.

## Декомпозиция

Из-за частичных зависимостей исходная таблица нарушает 2НФ. Выносим:

1. `nf_3_promotions(promo_id, promo_name, start_date, end_date, discount)`
2. `nf_3_products(product_id, category_name)`
3. `nf_3_sellers(seller_id, seller_city)`
4. `nf_3_promo_targets(promo_id, product_id, seller_id)`

После удаления частичных зависимостей не остаётся заданных транзитивных зависимостей, поэтому полученная схема находится в 3НФ.

## НФБК

В каждом итоговом отношении детерминант нетривиальной функциональной зависимости является ключом соответствующего отношения. Поэтому данная декомпозиция удовлетворяет НФБК и сохраняет указанные в задании зависимости.

Соединение без потерь обеспечивается тем, что `promo_targets` хранит внешние ключи на три справочных отношения, а его собственный ключ — исходный составной ключ.
