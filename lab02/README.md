## Цель работы

Связать операции теории множеств с `UNION`, `INTERSECT` и `EXCEPT` и показать отличие математического множества от мультимножества SQL.

Используется база Olist из практической работы № 1. Учитываются только заказы со статусом `delivered`.

- **A** — `product_id` товаров, которые покупали клиенты штата `RS`.
- **B** — `product_id` товаров, которые покупали клиенты штата `SC`.

## Результаты

| Показатель | Значение |
|---|---:|
| Строк в A до удаления дублей | 6134 |
| Уникальных товаров в A | 3939 |
| Строк в B до удаления дублей | 4097 |
| Уникальных товаров в B | 2740 |
| `A ∪ B` (`UNION`) | 5885 |
| `A ∩ B` (`INTERSECT`) | 794 |
| `A − B` (`EXCEPT`) | 3145 |
| `B − A` (`EXCEPT`) | 1946 |
| `A UNION ALL B` | 10231 |

Проверка мощности объединения:

`|A ∪ B| = |A| + |B| − |A ∩ B|`

`5885 = 3939 + 2740 − 794`

## Что выполнено

В `lab02.sql`:

- построены A и B;

- выполнены `UNION` и `UNION ALL`;

- показана некоммутативность разности;
- пересечение переписано через `EXISTS`;
- показано появление дублей без `DISTINCT`;
- добавлен итоговый запрос со всеми основными мощностями.

## Вывод

Обычный `SELECT` в SQL может содержать одинаковые строки, поэтому SQL работает не только с множествами, но и с мультимножествами.

`UNION`, `INTERSECT` и `EXCEPT` без `ALL` устраняют дубликаты. `UNION ALL` сохраняет их, поэтому в данной работе он возвращает 10231 строку вместо 5885 уникальных товаров.

Объединение и пересечение коммутативны: перестановка A и B не меняет результат. Разность некоммутативна: `A − B = 3145`, а `B − A = 1946`.
